# v0.7 Minimal Listener Runtime Approval Packet

This document fixes the approval evidence required before a separate minimal
listener runtime implementation PR can be considered. It is documentation,
fixture, and source-check test scope only. It does not implement listener
runtime behavior, socket behavior, transport, protocol handling, tool
registration, tool execution, local evidence reading, raw preview, replay,
active scan, or automatic ChatGPT handoff.

## Purpose

- Convert the v0.7 listener runtime decision preflight into a reviewable
  approval packet.
- Define the minimum conditions for a later listener runtime implementation PR.
- Keep listener runtime separate from transport, protocol handling, executable
  tool registration, actual tool execution, and local evidence reading.
- Keep the `v0.6` tag, GitHub Release `v0.6`, and four-file AI input candidate
  output bundle unchanged.

## Allowed Future Minimal Listener Boundary

A later minimal listener runtime PR may be considered only if it is:

- Local-only or loopback-only.
- Disabled by default.
- Limited to listener boundary behavior.
- Free of protocol parsing beyond blocked placeholder metadata.
- Free of executable tool registration.
- Free of actual tool execution.
- Free of local evidence body reads.
- Free of raw preview and raw download behavior.
- Free of automatic ChatGPT handoff.
- Covered by explicit negative tests.
- Covered by source-check declared file scope.
- Designed with raw-free error responses.

The later PR must not silently include transport, protocol handling, executable
tool registration, actual tool execution, local evidence reading, dashboard
state-changing actions, upload or import actions, or output bundle structure
changes.

## Required Runtime Constraints

Any later minimal listener runtime proposal must document:

- How the runtime stays local-only or loopback-only.
- How the runtime remains disabled by default.
- How remote bind behavior is blocked.
- How protocol messages are rejected until a separate protocol PR exists.
- How tool registration is absent.
- How tool execution is absent.
- How local evidence body reading is absent.
- How raw preview and download behavior are absent.
- How automatic handoff is absent.
- How errors remain raw-free.
- How the runtime can be disabled or rolled back.

## Required Negative Tests

A later runtime implementation PR must include negative tests for:

- `remote_bind_blocked`

- `tool_registration_absent`
- `tool_execution_absent`
- `local_evidence_read_absent`
- `raw_preview_absent`

These tests must be added in the later implementation PR, not in this approval

## Rollback and Disablement Expectations

A later minimal listener runtime implementation must have:

- A disabled-by-default mode.
- A documented disablement path.
- Raw-free blocked responses.
- A rollback plan that removes the listener runtime without touching the
  four-file AI input candidate output bundle.
- No release action unless separately approved.

This approval packet does not create the disablement mechanism. It only records
that the later runtime implementation must provide one.
