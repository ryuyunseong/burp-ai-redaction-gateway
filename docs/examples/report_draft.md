# 보안 점검 보고서 초안

이 문서는 기록에서 찾은 검토 후보를 정리한 초안이며, 취약점 확정 보고서가 아닙니다.
각 항목을 직접 확인한 뒤 실제 영향과 조치 내용을 보완하세요.

보고서 형식: 보수적 검토

공유 전 확인:
- 요청·응답 원문, 쿠키·인증 정보·토큰, 실제 도메인·IP·개인정보를 추가하지 마세요.
- 근거 신뢰도는 관찰한 자료의 신뢰 수준이며, 취약점의 심각도가 아닙니다.
- 위험도는 초안입니다. 직접 재현하고 별도로 위험을 평가한 뒤 확정하세요.

## 검토 후보 FC-0001: 보안 헤더 누락

- 대상 요청: GET /api/users/{id}/profile
- 근거 번호: EV-0001 / 직접 확인 필요: 예

### 발견 내용
- 응답에 없는 보안 헤더: Content-Security-Policy, Strict-Transport-Security, X-Content-Type-Options, X-Frame-Options

### 확인 방법
- 점검 환경에서 해당 요청이 HTTPS로 제공되는지 확인하세요.
- 운영 환경의 앞단 프록시에서 헤더를 추가하는지 확인하세요.

### 조치 제안
- 애플리케이션이나 앞단 서버에 적절한 보안 헤더를 설정하고 운영 환경에서도 적용되는지 확인하세요.

### 예상 영향
- 해당 환경에서 필요한 보안 헤더가 빠져 있다면 브라우저의 보호 기능이 줄어들 수 있습니다.

### 판단 근거
- 근거 신뢰도: 낮음
- 한 번의 응답에서 보안 헤더만 확인한 결과입니다.
- 앞단 프록시나 환경별 서버 설정에서 헤더를 추가할 수도 있습니다.
- 위험도 초안: 발생 가능성 낮음 / 영향 낮음 / 심각도 낮음
- 평가 기준: 보수적 검토 / 신중하게 판단
- 브라우저 보호에 미치는 영향은 배포 환경에 따라 다르므로 실제 서비스 경로에서 확인해야 합니다.

## 검토 후보 FC-0002: 쿠키 보호 설정 확인

- 대상 요청: GET /api/users/{id}/profile
- 근거 번호: EV-0001 / 직접 확인 필요: 예

### 발견 내용
- 쿠키 session에 없는 보호 속성: Secure

### 확인 방법
- 인증이나 로그인 상태 유지에 쓰는 쿠키인지 확인하세요.
- HTTPS 브라우저에서 Secure, HttpOnly, SameSite 속성이 작동하는지 확인하세요.

### 조치 제안
- 쿠키 용도에 맞게 Secure, HttpOnly, SameSite 보호 속성을 설정하세요.

### 예상 영향
- 인증이나 로그인 상태 유지에 쓰는 쿠키라면 보호 속성 누락으로 위험이 커질 수 있습니다.

### 판단 근거
- 근거 신뢰도: 보통
- 쿠키 값은 읽지 않고 Set-Cookie의 보호 속성만 확인했습니다.
- 로그인 상태 유지용으로 보이는 쿠키 이름: 있음
- Secure 또는 HttpOnly 속성 누락: 있음
- 쿠키 용도를 직접 확인하기 전의 근거 신뢰도: 보통
- 위험도 초안: 발생 가능성 낮음 / 영향 보통 / 심각도 낮음
- 평가 기준: 보수적 검토 / 신중하게 판단
- 영향을 확정하기 전에 쿠키 용도와 로그인 상태에 미치는 영향을 확인해야 합니다.

## 검토 후보 FC-0003: 로그인 응답의 캐시 설정 확인

- 대상 요청: GET /api/users/{id}/profile
- 근거 번호: EV-0001 / 직접 확인 필요: 예

### 발견 내용
- 인증 정보를 사용한 것으로 보이는 응답에 no-store, no-cache, private 캐시 설정이 없습니다.

### 확인 방법
- 응답에 사용자별 정보가 담겨 있는지 확인하세요.
- 로그인한 요청이 브라우저, 프록시, CDN에 어떻게 저장되는지 확인하세요.

### 조치 제안
- 로그인한 사용자별 응답에는 용도에 맞는 no-store, no-cache, private 캐시 정책을 적용하세요.

### 예상 영향
- 사용자별 정보가 담긴 응답이라면 의도하지 않은 곳에 임시 저장될 수 있습니다.

### 판단 근거
- 근거 신뢰도: 보통
- 정리된 기록에 인증 정보를 사용했다는 표시가 있습니다.
- Cache-Control에서 no-store, no-cache, private 설정이 확인되지 않았습니다.
- 사용자별 응답 단서: 있음
- 위험도 초안: 발생 가능성 낮음 / 영향 보통 / 심각도 낮음
- 평가 기준: 보수적 검토 / 신중하게 판단
- 캐시의 영향은 사용자별 정보가 담겨 있는지와 실제 저장 여부에 따라 달라집니다.

## 검토 후보 FC-0004: 다른 사용자 자료에 대한 접근 권한 확인 (IDOR)

- 대상 요청: GET /api/users/{id}/profile
- 근거 번호: EV-0001 / 직접 확인 필요: 예

### 발견 내용
- 요청 경로나 매개변수에 식별자가 있습니다.
- 인증 정보를 사용한 것으로 보이는 요청이 성공 응답(HTTP 2xx)을 받았습니다.
- 응답 구조에 사용자별 정보 항목이 있습니다.
- 서로 다른 권한의 계정으로 직접 확인해야 합니다.

### 확인 방법
- 서로 다른 두 테스트 계정으로 응답을 비교하세요.
- 식별자만 바꿨을 때 다른 테스트 계정의 자료에 접근할 수 있는지 확인하세요.
- 화면에서 버튼을 숨기는 것과 별개로 서버에서 접근 권한을 검사하는지 확인하세요.

### 조치 제안
- 자료에 접근할 때마다 서버에서 로그인한 사용자와 자료 소유자를 기준으로 권한을 확인하세요.

### 예상 영향
- 식별자만 바꿔 다른 사용자의 자료에 접근할 수 있다면 접근 권한 검사에 문제가 있을 수 있습니다.

### 판단 근거
- 근거 신뢰도: 보통
- 식별자, 인증 정보 사용 흔적, 성공 응답(HTTP 2xx), 사용자별 응답 구조가 함께 확인됐습니다.
- 다른 사용자나 권한으로 접근하는 검사는 하지 않았으므로 직접 확인해야 합니다.
- 위험도 초안: 발생 가능성 보통 / 영향 보통 / 심각도 보통
- 평가 기준: 보수적 검토 / 신중하게 판단
- 자료별 접근 권한 문제의 심각도는 다른 사용자나 권한으로 재현한 뒤 판단해야 합니다.

## 검토 후보 FC-0005: 응답의 민감정보 포함 여부 확인

- 대상 요청: GET /api/users/{id}/profile
- 근거 번호: EV-0001 / 직접 확인 필요: 예

### 발견 내용
- 응답 구조에 민감정보 제거 대상 항목이 있습니다.
- 민감정보 제거 대상 항목 수: 2개

### 확인 방법
- 각 민감정보 항목이 해당 기능에 꼭 필요한지 확인하세요.
- 권한별 접근 범위와 필요한 정보만 반환하는지 확인하세요.

### 조치 제안
- 응답에는 필요한 정보만 담고, 권한에 따라 표시할 항목을 제한하세요.

### 예상 영향
- 사용자의 권한이나 업무에 필요하지 않은 항목이라면 불필요한 정보가 응답에 포함될 수 있습니다.

### 판단 근거
- 근거 신뢰도: 보통
- 응답 구조에 민감정보를 제거한 항목 표시가 있습니다.
- 인증 정보 사용 또는 사용자별 응답 단서: 있음
- 업무상 필요한 정보인지, 해당 권한에서 보여도 되는지 직접 검토해야 합니다.
- 위험도 초안: 발생 가능성 보통 / 영향 보통 / 심각도 보통
- 평가 기준: 보수적 검토 / 신중하게 판단
- 정보 노출의 영향은 업무상 필요성, 권한별 표시 범위, 불필요한 정보 포함 여부를 검토해 판단해야 합니다.
