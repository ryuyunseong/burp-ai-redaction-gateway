# v0.6 RC Readiness Checklist

This checklist records the conditions for treating the current v0.6 line as an
RC candidate. It is documentation and test evidence only. It does not create a
tag, create a GitHub Release, implement an MCP listener, implement transport,
implement protocol handling, execute tools, read local evidence bodies, expose
raw previews, replay traffic, run active scan behavior, or send anything to
ChatGPT automatically.

## Purpose

- Convert the current v0.6 safety and UX baseline into an RC decision checklist.
- Keep release readiness separate from tag creation and GitHub Release creation.
- Keep the operator flow local-first, raw-free, read-only, and manual-review
  based.
- Keep MCP runtime surface closed until a separate approved implementation PR.

## Release Blockers

- Full gate failure.
- Gitleaks failure.
- Git safety failure.
- Raw request or raw response marker appears in tracked output, PR body, or
  release notes.
- Actual target, domain, IP, credential, token, or session values appear in
  tracked output, PR body, or release notes.
- Full local path appears in tracked output, PR body, or release notes.
- Sharing guarantee wording appears.
- Confirmed issue or CVSS certainty wording appears.
- MCP listener, transport, protocol handling, tool execution, or local evidence
  reader is added before approval.
- Automatic ChatGPT handoff is added.
- Raw preview or raw download is added.
- Tag or GitHub Release is created without explicit approval.

## Explicit Non-Goals

- MCP server listener implementation.
- MCP transport implementation.
- MCP protocol handler implementation.
- Executable tool registration implementation.
- Actual tool execution implementation.
- Local evidence reader implementation.
- Safe file body reader implementation.
- Upload, import, or dashboard POST action implementation.
- Collector forwarding behavior change.
- Receiver ingest behavior change.
- Raw preview or raw download implementation.
- Replay or active scan implementation.
- Automatic ChatGPT handoff implementation.
- Output bundle four-file structure change.
- New tag creation.
- GitHub Release creation.

## Tag And GitHub Release Decision

- No tag until explicit approval.
- No GitHub Release until explicit approval.
- A passing checklist means RC judgment is possible; it does not publish a
  release.
- Tag target and release notes must be checked again before any release action.
