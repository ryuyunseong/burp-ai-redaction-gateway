# v0.5 Hotfix Policy

`v0.5` is the published local-use baseline. This policy defines what may be
considered for a v0.5.x patch and what must move to v0.6 or a separate security
review.

This document is policy only. It does not change runtime behavior, collector
forwarding, receiver ingest, dashboard actions, MCP behavior, redaction rules,
HMAC behavior, CSRF behavior, retention behavior, tags, or GitHub Releases.

## Allowed v0.5.x Hotfix Scope

A v0.5.x hotfix may be considered for narrow maintenance work:

- Release note typo.
- Broken link fix.
- Documentation correction.
- Failing test fix.
- Packaging or launch script bug.
- Dashboard copy bug.
- Non-behavioral safety wording correction.

Hotfix acceptance criteria:

- The change does not add a new feature.
- The change does not alter capture, ingest, redaction, verification, report,
  audit, archive, or dashboard action behavior.
- The change keeps finding language candidate-only.
- The change keeps risk language draft-only.
- Severity and CVSS values remain manual decisions.
- The change passes the standard verification gate for the affected area.

## Not Allowed In v0.5.x

The following items must not be treated as v0.5.x hotfixes:

- MCP server implementation.
- Local evidence reader.
- New POST action.
- Collector forwarding behavior change.
- Receiver ingest behavior change.
- Raw preview or raw download.
- Replay or active scan.
- ChatGPT auto-send.
- File delete or retention policy change.
- HMAC or CSRF behavior change.

These items belong in v0.6 or a separate security-focused PR after design
review.

## Decision Checklist

Use this checklist before labeling work as a v0.5.x hotfix:

- Is this a regression, broken link, typo, launch issue, packaging issue, or
  failing test? If yes, hotfix may be appropriate.
- Does this add a route, tool, POST action, file intake, handoff, preview,
  replay, active scan, or policy behavior? If yes, move it to v0.6.
- Does this touch raw handling, credential/session handling, HMAC, CSRF,
  retention, deletion, collector forwarding, receiver ingest, or external
  handoff behavior? If yes, split it into a dedicated security review PR.
- Does this require new operator approval or state-changing UI behavior? If
  yes, do not treat it as a hotfix.

## Required Verification

Use the standard gate that fits the patch. For release-affecting patches, use:

- Python compileall.
- Python unittest.
- `verify --input out`.
- Demo review and report generation.
- Montoya collector build when the collector tree is present or referenced.
- Gitleaks directory scan.
- Gitleaks git history scan.
- Git safety check.
- Git diff whitespace check.
- Git status clean check.

## Documentation Hygiene

Hotfix notes, PR bodies, release text, and issue text must stay raw-free.
Do not include:

- Raw request or response values.
- Real target identifiers.
- Credential or session values.
- Personal data.
- HMAC secret values.
- CSRF token values.
- Full local path details.
- Actual local-only evidence filenames.
- Raw audit rows.
- Archive content.
- Sharing approval language.
- Vulnerability confirmation language.
- Automatic severity or CVSS confirmation language.
