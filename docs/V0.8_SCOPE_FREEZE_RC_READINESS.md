# v0.8 Scope Freeze and RC Readiness

This document fixes the recommended v0.8 release scope as a boundary/helper
release candidate. It records the PR #130 helper merge and PR #131 post-merge
boundary note as the current baseline, then separates release readiness from
any future read-only MCP runtime work.

This is release readiness evidence only. It does not add runtime behavior,
parser behavior, request dispatch, tool execution, local evidence reading, raw
preview or download, dashboard state-changing controls, upload or import
actions, replay, active scan, automatic ChatGPT handoff, tag changes, or
GitHub Release changes.

## Purpose

- Freeze v0.8 as a boundary/helper release candidate.
- Keep the current v0.8 release path narrow, reviewable, and rollback-friendly.
- Preserve the four-file AI input candidate boundary.
- Keep runtime, parser, dispatcher, tool, evidence, dashboard action, upload,
  and handoff work deferred to separate approval PRs.
- Keep v0.8 tag and GitHub Release work blocked until explicit release
  approval.

The current scope freeze is based on these merged PRs:

- PR #130 merge commit `fcc0dd947ec9c62410cc5715cce7ae623bc32aa8`
- PR #131 merge commit `bb484ea21d90759125a7224fedaec6a9ee7b75fc`

## Recommended release type

The recommended v0.8 release type is `boundary_helper`.

This means v0.8 should stop at:

- existing redaction, verify, review, and report pipeline behavior
- the four AI input candidate files
- dashboard read-only and raw-free guidance
- disabled-by-default MCP helper files
- post-merge boundary note
- source-check and fixture guard evidence
- release readiness evidence

It should not be described as a read-only MCP runtime release.

## Release blockers

The v0.8 release action must stay blocked if any of these are true:

- unit tests fail
- gitleaks directory scan reports a finding
- gitleaks git scan reports a finding
- git safety check fails
- document or fixture hygiene finds a raw marker or credential marker
- v0.8 tag already exists unexpectedly
- GitHub Release v0.8 already exists unexpectedly
- unreviewed runtime surface is present
- output bundle structure changes
- tag or GitHub Release mutation is requested before explicit approval

## Required final gate

Before release approval, rerun at least:

- Python compile check
- Python unit test discovery
- gitleaks directory scan
- gitleaks git scan
- git safety check
- diff whitespace check
- clean working tree check
- tag absence check
- GitHub Release absence check

Any broader final gate may add verify, review, report, or collector build checks,
but this scope freeze document does not create those outputs or mutate release
state.

## Rollback expectation

- Before a tag exists, rollback means reverting only the release-prep PR that
  introduced this scope freeze evidence.
- Do not move a tag before explicit release approval.
- Do not mutate a GitHub Release before explicit release approval.
- If release blockers appear, keep the scope freeze PR separate from runtime
  implementation fixes.
