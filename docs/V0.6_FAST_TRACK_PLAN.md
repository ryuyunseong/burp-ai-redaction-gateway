# v0.6 Fast-Track Plan

This planning only document groups v0.6 work into reviewable slices. It now
tracks completed read-only UX slices as well as the next planning candidates.
It does not implement an MCP server, MCP transport, tool handler, local evidence
reader, dashboard POST action, upload or import action, collector forwarding
change, receiver ingest change, raw preview, replay, active scan, automatic
ChatGPT handoff, tag, or GitHub Release.

## Goals

- Keep the gateway local-first and raw-free at every user-facing boundary.
- Move quickly on read-only UX and documentation slices.
- Split security-sensitive runtime or state-changing work into separate PRs.
- Keep findings as candidates until manual review.
- Keep risk values as drafts until manual review.
- Keep severity and CVSS as manual decisions.
- Keep AI input limited to the four candidate safe files.

## Completed Read-Only UX Slice

The read-only dashboard UX bundle has landed on `main` as a completed v0.6
slice. It delivered:

- Output alias copy that keeps aliases separate from local paths and target
  identifiers.
- Troubleshooting categories linked only to existing dashboard routes.
- Release readiness status metadata with document filenames shown as
  non-serving reference text.
- Tests and browser smoke for no POST forms, no buttons, no `href="docs/`, and
  no raw or credential markers.

This completed slice does not approve tags, GitHub Releases, MCP runtime work,
or state-changing dashboard actions.

## Two-Week Candidate Sequence

This schedule is a planning aid, not a commitment.

1. Keep the merged output alias selector and read-only dashboard UX bundle as
   completed baseline slices.
2. Add or refresh this fast-track plan and its document hygiene test.
3. Draft the MCP registry adapter design and fixture matrix.
4. Decide whether the first MCP prototype can remain read-only and local-only.
5. Defer any runtime-affecting implementation until the design and fixtures are
   reviewed.

## Required Completion Criteria Per PR

Each PR in this track should include:

- One narrow read-only objective.
- Tests for the new document, route, or fixture.
- Browser or smoke evidence when a dashboard surface changes.
- Raw-free wording that avoids guarantee language.
- Explicit confirmation that no state-changing action was added.
- Explicit confirmation that no tag or GitHub Release was created.
- `git diff --check` and the standard local gates for the changed area.

## Work That Must Stay Separate

The following work changes security, transport, state, or raw-data boundaries.
Keep each as a separate design or implementation PR.

- MCP server implementation.
- MCP transport implementation.
- Tool handler implementation.
- Local evidence reader.
- Upload or import evidence action.
- Dashboard POST action.
- Collector forwarding change.
- Receiver ingest change.
- Raw preview or raw download.
- Replay.
- Active scan.
- Automatic ChatGPT handoff.
- File delete or retention behavior change.
- HMAC behavior change.
- CSRF behavior change.

## Boundary Checklist

Before moving any v0.6 PR out of Draft, confirm:

- The change is read-only unless the PR is explicitly scoped as a
  state-changing security review.
- The page, document, or fixture uses aliases and counts instead of local
  paths, target identifiers, raw traffic, or credential values.
- The four AI candidate safe files remain the only AI input candidates.
- Candidate findings are not treated as confirmed issues.
- Draft risk values are not treated as final severity.
- Severity and CVSS decisions remain manual.
- Passing smoke evidence is readiness evidence only.
- Tags and GitHub Releases remain separate release-management actions.

## Deferred Decisions

- Whether a read-only MCP prototype can ship without any local evidence reader.
- Which v0.6 slice should become the first runtime-affecting PR.
- What additional browser smoke should be required before state-changing
  dashboard actions are considered.
