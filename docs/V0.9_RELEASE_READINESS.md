## Raw-free assurance limits

The readiness record is metadata-only and does not include raw traffic,
credential values, target identifiers, local file bodies, or release artifacts.
It does not guarantee external publication approval. A human reviewer must
confirm the final release notes, target commit, and deferred scope before a tag
or GitHub Release is created.

## Tag and GitHub Release preconditions

Before a v0.9 tag or GitHub Release can be created:

- the release candidate commit must match this readiness baseline or the
  readiness document must be updated;
- the full gate set must be rerun on the target commit;
- no deferred runtime surface may be introduced;
- the release body must state the safe-core scope and deferred scope;
- tag creation and GitHub Release publication require explicit approval.

## Rollback plan

If the readiness PR is incorrect, revert only the readiness PR. If a future
v0.9 tag or GitHub Release is created on the wrong commit, stop publication,
record the mismatch, and request explicit maintainer approval before any
corrective release action.
