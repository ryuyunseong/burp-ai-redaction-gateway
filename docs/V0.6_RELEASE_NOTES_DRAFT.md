# v0.6 Release Notes Draft

This document is a release notes draft only. It is not a tag, not a GitHub
Release, not release approval, and not external sharing approval. It records
the intended v0.6 operator-facing summary while keeping the actual release
action behind a separate explicit approval.

## Purpose

- Draft the v0.6 release story before any tag or GitHub Release action.
- Keep the release language aligned with the RC readiness checklist.
- Keep candidate finding, draft risk, draft report, and manual severity/CVSS
  boundaries visible.
- Keep MCP runtime surface closed until a separate approved implementation PR.

## Draft Release Summary

v0.6 focuses on making the local redaction, verify, review, report, and
operator dashboard flow easier to follow before opening new runtime MCP
surfaces. The main release theme is local-first evidence handling with a clear
four-file output bundle and explicit manual review before AI use.

## User-Visible Changes

- Korean quickstart guidance for the core local workflow.
- Output bundle guide that separates basic and advanced files.
- Simple Dashboard wording that highlights verify status, candidate findings,
  draft risk, draft report, and manual severity/CVSS decisions.
- RC readiness checklist with gate, smoke, UX, output bundle, MCP boundary, and
  blocker criteria.
- Quickstart smoke procedure for the generate, verify, review, report, and
  Simple Dashboard path.

## Security And Privacy Boundaries

- Raw traffic is not an AI input candidate.
- Automatic ChatGPT handoff is not implemented.
- Manual review is required before any AI use.
- Finding records are candidate finding records.
- Risk values are draft risk values.
- Report output is a draft report.
- Severity/CVSS values require manual decision.
- Smoke results are readiness evidence only.
- A passing smoke does not approve external sharing.
- A passing smoke does not approve release publishing.

## Output Bundle

The v0.6 output bundle remains limited to four AI input candidate files:

- `analysis_packet.json`
- `chatgpt_prompt.md`
- `codex_task_prompt.md`
- `report_draft.md`

Basic view:

- `report_draft.md`
- `chatgpt_prompt.md`

Advanced view:

- `analysis_packet.json`
- `codex_task_prompt.md`

The four-file structure is unchanged by this draft.

## Dashboard UX

The Simple Dashboard remains a read-only operator check. It should help an
operator confirm:

- Verify status.
- Candidate finding count.
- Basic view and advanced view files.
- Manual review requirement.
- Draft risk and draft report boundaries.
- No automatic ChatGPT handoff.

## MCP Status

The following are not implemented in this release notes draft:

- MCP server listener.
- MCP transport.
- MCP protocol handler.
- Executable tool registration.
- Actual tool execution.
- Local evidence reader.
- Safe file body reader.

MCP work remains bounded by registry, fixture, dry-run, schema catalog,
source-check, and boundary documentation until a separate approved runtime PR.

## Verification Evidence Required Before Release

Before any v0.6 tag or GitHub Release action, rerun and record:

- `python -m compileall burp_ai_redaction_gateway tests`
- `python -m unittest discover -s tests`
- `python -m burp_ai_redaction_gateway verify --input out`
- `python -m burp_ai_redaction_gateway review --input out\demo`
- `python -m burp_ai_redaction_gateway report --input out\demo --output out\demo\report_draft.md --profile conservative`
- `extensions\montoya-collector\gradlew.bat clean build`
- `gitleaks dir -v --redact=100 --config .gitleaks.toml .`
- `gitleaks git -v --redact=100 --config .gitleaks.toml .`
- `scripts\git_safety_check.bat`
- `git diff --check`
- `git status --short --untracked-files=all`
- Quickstart smoke for generate, verify, review, report, and Simple Dashboard.

- Release notes must be checked again before any publish action.
