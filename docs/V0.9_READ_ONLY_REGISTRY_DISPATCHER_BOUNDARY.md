# v0.9 Read-only Registry Dispatcher Boundary

## Purpose

This decision fixes the boundary between the v0.9 read-only registry metadata
helper and any future dispatcher work. The registry helper is now available as
metadata-only code, but it must not be treated as dispatcher approval,
executable registration, actual tool execution, or local evidence access.

## Boundary Decision

The read-only registry metadata helper is not dispatcher approval. It is not
executable registration. It is not actual tool execution. It only validates the
registry contract and implementation guard fixtures, then returns the allowed
metadata fields fixed by the registry contract.

Dispatcher invocation remains blocked until a separate approval packet defines
the input, output, blocked response, audit, and negative-test boundary for that
surface.

## Explicit Non-goals

This decision does not approve:

- dispatcher implementation
- dispatcher invocation
- executable tool registration
- actual tool execution
- listener startup
- transport runtime
- local evidence reader
- safe file body reader
- raw preview or download
- replay or active scan
- dashboard state-changing control
- upload or import action
- automatic ChatGPT handoff
- v0.9 tag creation
- GitHub Release v0.9 creation

## Registry Metadata Scope

The registry helper may return only the fields from
`allowed_registry_metadata_fields`:

- `registry_schema_version`
- `registry_contract_only`
- `read_only_capability_labels`
- `tool_execution_allowed`
- `dispatcher_invocation_allowed`
- `local_evidence_access_allowed`
- `raw_data_included`
- `manual_review_required`

The `read_only_capability_labels` values are metadata labels only. They are not
tool objects, callbacks, handlers, commands, or executable registrations.

The safe file inventory label means four-file candidate inventory metadata
only. It does not approve reading file bodies.

## Dispatcher Invocation Boundary

Dispatcher invocation is blocked until a later approval packet explicitly
defines the dispatcher contract. The registry helper must not:

- receive parser output and dispatch it
- map capability labels to callable handlers
- route any request to a tool implementation
- return dispatcher callback metadata
- produce a tool execution result

## Executable Registration Boundary

Executable tool registration is blocked until a separate decision. The registry
helper must not expose executable registration fields, handler names, callback
handles, command strings, or tool lookup tables.

## Actual Tool Execution Boundary

Actual tool execution is blocked until a dedicated threat-boundary review. The
registry helper must not call tools, read output file bodies, perform dashboard
state changes, upload or import data, replay traffic, start active scans, or
send data to ChatGPT.

## Source-check Requirements

Runtime-facing registry source files must remain free of dispatcher,
registration, execution, local evidence, listener, transport, and network
startup markers. Source checks must include the registry helper source and must
fail if forbidden implementation markers appear without a separate approval.

- Confirm false-only flags remain false.
- Confirm capability labels are metadata labels only.
- Confirm no dispatcher invocation is introduced.
- Confirm no executable registration is introduced.
- Confirm no actual tool execution is introduced.
- Confirm no local evidence reader or safe file body reader is introduced.
- Confirm no tag or GitHub Release is created by this work.
