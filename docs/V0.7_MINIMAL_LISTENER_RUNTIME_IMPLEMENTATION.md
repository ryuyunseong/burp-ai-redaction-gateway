# v0.7 Minimal Listener Runtime Implementation

This document records the first minimal listener runtime implementation slice.
It implements only disabled-by-default, local-only, loopback-only listener
boundary helpers and raw-free blocked or disabled response metadata.

This implementation does not start a long-running listener. It does not add MCP
transport, protocol handling, executable tool registration, actual tool
execution, local evidence reading, safe file body reading, raw preview,
replay, active scan, dashboard state-changing control, upload or import action,
or automatic ChatGPT handoff.

## Purpose

- Consume the v0.7 minimal listener runtime implementation decision.
- Add a small runtime helper that validates disabled/default and loopback-only
  startup constraints without opening any transport or protocol surface.
- Connect the runtime source-check consumption guard to the new listener-facing
  source file.
- Connect the negative test harness design to executable tests.
- Keep the four-file AI input candidate output bundle unchanged.

The source-check guard is tracked in
[`V0.7_RUNTIME_SOURCE_CHECK_CONSUMPTION.md`](V0.7_RUNTIME_SOURCE_CHECK_CONSUMPTION.md).
The local smoke evidence fixture is tracked in
[`V0.7_LISTENER_LOCAL_SMOKE_EVIDENCE.md`](V0.7_LISTENER_LOCAL_SMOKE_EVIDENCE.md).

## Implemented Boundary

The implementation is limited to:

- `burp_ai_redaction_gateway/mcp_listener_runtime.py`
- disabled-by-default listener runtime configuration
- loopback-only host validation
- remote or non-loopback host rejection metadata
- protocol-like message rejection metadata
- raw-free disabled and blocked responses
- local smoke summary metadata
- source-check fixture consumption
- negative harness fixture consumption

The helper returns metadata. It does not start a long-running service and does
not read local evidence or safe file bodies.

## Disabled-by-default Behavior

The default configuration keeps the listener runtime disabled. Disabled startup
validation returns:

- `status: disabled`
- `reason_code: listener_disabled`
- `raw_data_included: false`
- `manual_review_required: true`
- `listener_started: false`

The response contains stable metadata only and does not echo caller input.
Disabled startup validation returns before interpreting caller input, including
protocol-like bodies. Protocol-like input is rejected only after the runtime is
explicitly enabled and loopback startup validation is being evaluated.

## Loopback-only Behavior

When explicitly enabled for validation, the helper accepts only loopback host
metadata. Non-loopback and wildcard-style host values are blocked before any
runtime startup is permitted.
All-interface host values are treated as remote bind attempts and return
`remote_bind_blocked` without echoing the supplied host value.

The blocked response uses stable reason codes and does not include host values,
target identifiers, raw caller body, credential values, local paths, stack
trace body, or safe file body preview.

## Raw-free Response Contract

All blocked and disabled responses include:

- `metadata_only: true`
- `raw_data_included: false`
- `manual_review_required: true`
- `listener_started: false`

Reason codes are allowlisted. Unknown or caller-controlled body values are not
echoed into the response.
Statuses are also allowlisted. Unknown or caller-controlled status values are
normalized to stable blocked metadata before the response is returned.

- `burp_ai_redaction_gateway/mcp_listener_skeleton.py`

## Local Smoke

The local smoke helper validates:

- default disabled behavior
- loopback startup validation metadata
- non-loopback rejection metadata
- raw-free response contract
- no listener startup side effect

Smoke output is metadata only and must not contain target identifiers, raw
traffic, credential values, local paths, stack trace body, or safe file body
preview.
The local smoke evidence document records those checks as release-readiness
input only. It does not approve tag creation or GitHub Release work.
The v0.7 RC readiness checklist is tracked in
[`V0.7_RC_READINESS_CHECKLIST.md`](V0.7_RC_READINESS_CHECKLIST.md). It consumes
the smoke evidence as one checklist input and still does not approve tag
creation or GitHub Release work.
