## Startup implementation decision

The approval result is `review_only`. Actual listener startup remains blocked
after this review. A later implementation PR must explicitly consume this
review and must still keep startup, transport, protocol handling, tool
execution, and local evidence reading split unless a separate approval narrows
that scope.

## Socket boundary

Socket startup remains forbidden in this review. A later startup PR must keep
socket bind, listen, and accept behavior separate from protocol handling, tool
execution, local evidence reading, and raw preview. Any combined PR that opens
startup and another runtime surface is blocked.

## Loopback-only requirement

Any future startup implementation must be loopback-only. Non-loopback bind
plans must fail closed before runtime. This review does not bind a socket and
does not create a server.

## Origin validation requirement

Any future HTTP transport path must define origin validation before runtime.
Missing, unsupported, or untrusted origin metadata must block startup with
raw-free metadata. This review does not parse headers or accept protocol
messages.

## Authentication boundary

Remote transport requires a separate authentication and authorization boundary.
This review does not introduce authentication, delegated access, credential
forwarding, executable registration, or tool invocation.

## Session policy

Stateful transport requires a session policy before runtime. Session
identifiers must not be treated as authentication. Session identifiers must be
secure, non-deterministic, and should bind to user context where applicable.
Session identifiers and credential-derived values must not be logged or echoed.

## Token passthrough prohibition

Token passthrough is forbidden. Caller-provided credential values must not be
forwarded to tools, adapters, local evidence readers, dashboard actions, or
external services as an authorization substitute.
