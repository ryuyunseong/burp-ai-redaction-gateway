# v0.6 Quickstart Smoke

This document records a quick, raw-free smoke path for the v0.6 RC candidate
workflow. It is a local operator check only. It does not create a tag, create a
GitHub Release, approve external sharing, implement an MCP listener, implement
transport, implement protocol handling, register executable tools, execute
tools, read local evidence bodies, expose raw previews, replay traffic, run
active scan behavior, or send anything to ChatGPT automatically.

## Purpose

- Confirm that a new operator can follow the core local flow.
- Confirm that the safe output bundle still contains exactly the four AI input
  candidate files.
- Confirm that Simple Dashboard copy keeps the basic and advanced views clear.
- Keep the smoke result separate from release approval and external sharing.

## Smoke Scope

Included:

- Generate sanitized output from a synthetic sample.
- Verify generated output.
- Review candidate findings.
- Generate a draft report.
- Open the Simple Dashboard route for the smoke project alias.
- Confirm the four output bundle files are present as AI input candidates.

Excluded:

- Actual Burp target traffic.
- Raw traffic handoff to AI.
- Automatic ChatGPT handoff.
- MCP listener, transport, protocol, or tool execution.
- Local evidence reader or safe file body reader.
- Raw preview, raw download, replay, or active scan.
- Tag creation or GitHub Release creation.

## Preconditions

- Work from a clean repository checkout.
- Use the tracked synthetic sample only.
- Keep local-only files, ignored output, and raw evidence out of commits.
- Treat this smoke as readiness evidence only.

## Commands

Run from the repository root:

```powershell
python -m burp_ai_redaction_gateway generate --input samples\synthetic_burp_history.json --output out\quickstart_smoke --project quickstart_smoke
python -m burp_ai_redaction_gateway verify --input out\quickstart_smoke
python -m burp_ai_redaction_gateway review --input out\quickstart_smoke
python -m burp_ai_redaction_gateway report --input out\quickstart_smoke --output out\quickstart_smoke\report_draft.md --profile conservative
python -m burp_ai_redaction_gateway dashboard --root out
```

After the dashboard starts, open the Simple Dashboard route:

```text
/simple?project=quickstart_smoke
```

## Expected Output

- `generate` writes sanitized output files under the smoke output alias.
- `verify` passes before review, report, dashboard, or AI use.
- `review` prints candidate finding counts and safe prompt file names only.
- `report` writes `report_draft.md`.
- `Raw data included: false` remains visible in review and report summaries.
- No raw traffic, credential value, session value, target identifier, or full
  local path is needed in the smoke note.

## Dashboard Simple Check

The Simple Dashboard check should show:

- Basic view: `report_draft.md`, `chatgpt_prompt.md`.
- Advanced view: `analysis_packet.json`, `codex_task_prompt.md`.
- Verify status before AI use.
- Candidate finding wording.
- Draft risk wording.
- Draft report wording.
- Severity/CVSS manual decision wording.
- Manual review required before any AI use.
- No automatic ChatGPT handoff.

The Simple Dashboard check should not show:

- Raw request or response body.
- Credential, token, or session values.
- Actual target identifiers.
- Full local paths.
- Form, POST action, raw preview, raw download, replay, or active scan action.

## Output Bundle Check

The only AI input candidate files are:

- `analysis_packet.json`
- `chatgpt_prompt.md`
- `codex_task_prompt.md`
- `report_draft.md`

Basic view:

- `report_draft.md`
- `chatgpt_prompt.md`

Advanced view:

- `analysis_packet.json`
- `codex_task_prompt.md`

All four files require manual review before any AI use. The output bundle is
not a sharing guarantee.

## Security Checks

- Run the RC checklist gate before release decisions.
- Keep finding language as candidate finding.
- Keep risk language as draft risk.
- Keep report language as draft report.
- Keep severity/CVSS as manual decision.
- Keep AI handoff manual.
- Keep raw traffic out of PR bodies, release notes, smoke notes, and dashboard
  copy.

## Failure Handling

If any step fails:

- Stop the smoke.
- Keep the result as failed readiness evidence.
- Do not create a tag.
- Do not create a GitHub Release.
- Do not treat output files as AI-ready.
- Record only raw-free metadata such as command name, project alias, pass/fail
  label, and safe file names.

## Non-Goals

- MCP server listener implementation.
- MCP transport implementation.
- MCP protocol handler implementation.
- Executable tool registration implementation.
- Actual tool execution implementation.
- Local evidence reader implementation.
- Safe file body reader implementation.
- Raw preview or raw download implementation.
- Replay or active scan implementation.
- Automatic ChatGPT handoff implementation.
- Output bundle four-file structure change.
- New tag creation.
- GitHub Release creation.
