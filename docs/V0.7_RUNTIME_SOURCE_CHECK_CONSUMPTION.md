# v0.7 Runtime Source-check Consumption

This document fixes the source-check consumption guard for v0.7 runtime-facing
listener files. The guard itself is documentation, fixture, and test scope only. It
does not add transport, protocol handling, executable tool registration, actual
tool execution, local evidence reading, safe file body reading, raw preview,
replay, active scan, dashboard state-changing control, upload or import action,
or automatic ChatGPT handoff.

## Purpose

- Ensure later runtime-facing files cannot bypass the declared source-check
  guard.
- Connect the v0.7 minimal listener runtime design fixture to the existing
  runtime-facing source-check policy.
- Keep future listener runtime implementation separate from transport,
  protocol handling, executable tool registration, actual tool execution, local
  evidence reading, and dashboard state-changing controls.
- Keep the `v0.6` tag, GitHub Release `v0.6`, and four-file AI input candidate
  output bundle unchanged.

## Forbidden Source Markers

Declared runtime-facing source files must not contain:

- `http.server`
- `socketserver`
- `http.client`
- `socket`
- `subprocess`
- `requests`
- `urllib`
- `bind(`
- `listen(`
- `accept(`
- `serve_forever`
- `run_server`
- `create_server`
- `register_tool`
- `dispatch_tool`
- `tool_execute`
- `execute_tool`
- `read_local_evidence`
- `read_file_body`
- `raw_preview`
- `replay`
- `active_scan`

These markers are source-check inputs only. Their presence in this document or
the fixture records what is blocked; their presence in declared runtime-facing
source files remains forbidden.

The current metadata-only skeleton may contain blocked-surface labels that name
disabled behavior, such as `raw_preview_download`. Those labels are not runtime
implementation. The source-check test strips only the explicitly allowed
metadata labels before checking forbidden implementation markers.
