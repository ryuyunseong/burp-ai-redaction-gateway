# v0.7 Listener Runtime Decision Preflight

This document fixes the decision and preflight guard before any v0.7 MCP
listener runtime work starts. It is documentation, fixture, and source-check
test scope only. It does not implement a listener, transport, protocol handler,
tool registration, tool execution, local evidence reader, raw preview, or
automatic ChatGPT handoff.

## Purpose

- Consume the metadata-only listener skeleton before any runtime listener work.
- Keep the current listener-facing helper as metadata-only.
- Define the minimum preflight evidence required before a runtime listener can
  be proposed.
- Keep listener runtime, transport, protocol handling, executable tool
  registration, actual tool execution, and local evidence reading as separate
  review boundaries.
- Keep the `v0.6` tag, GitHub Release `v0.6`, and four-file AI input candidate
  output bundle unchanged.

## Current Baseline

The current baseline includes:

- Published `v0.6` release state.
- Completed `v0.6.1` hotfix triage criteria.
- v0.7 scope planning.
- v0.7 metadata-only MCP listener skeleton planning.
- `burp_ai_redaction_gateway/mcp_listener_skeleton.py` as a metadata-only
  helper.

The current baseline does not include listener runtime behavior, transport,
protocol handling, executable tool registration, actual tool execution, local
evidence reading, raw preview, replay, active scan, or automatic ChatGPT
handoff.

## Decision Scope

This preflight decides what must be true before a separate listener runtime PR
can be considered. It does not approve that runtime PR.

The decision scope is limited to:

- Required planning inputs.
- Required fixture fields.
- Required negative tests.
- Required source-check coverage.
- PR split rules for later runtime work.
- Continued raw-free and read-only wording boundaries.

## Allowed Future Listener Boundary

A later listener runtime PR may be considered only after this preflight remains
green and the later PR states its exact boundary. The allowed future listener
boundary must be limited to listener behavior only, and must not silently include
transport, protocol handling, executable tool registration, actual tool
execution, local evidence reading, safe file body reading, raw preview, replay,
active scan, or automatic ChatGPT handoff.

Any later listener runtime PR must keep the four-file AI input candidate output
bundle unchanged unless a separate output-bundle PR is approved first.

## Forbidden Runtime Surfaces

This preflight keeps the following surfaces forbidden:

- MCP server listener runtime.
- Socket bind, listen, accept, and long-running server loops.
- stdio, HTTP, or other MCP transport implementation.
- JSON-RPC or MCP protocol handler.
- MCP protocol message parser.
- Executable tool registration.
- Actual tool execution.
- Local evidence reader.
- Safe file body reader.
- Upload or import action.
- Dashboard state-changing action.
- Raw preview or raw download.
- Replay or active scan.
- Automatic ChatGPT handoff.
- Tag or GitHub Release action.

## Required Acceptance Criteria

- This document exists.
- The runtime decision preflight fixture exists.
- The v0.7 scope plan links to this document.
- The v0.7 listener skeleton plan links to this document.
- The fixture has `planning_only` set to true.
- The fixture has `metadata_only_skeleton_consumed` set to true.
- The fixture has `v07_listener_skeleton_plan_consumed` set to true.
- The fixture has listener runtime approval and implementation flags set to
  false.
- Transport, protocol, tool execution, and local evidence reader flags remain
  false.
- Source-check is required before runtime.
- Negative tests are required before runtime.
- The existing metadata-only listener skeleton file is listed.
- The existing metadata-only listener skeleton file contains no forbidden
  source markers.

## Required Negative Tests

Tests must fail if:

- This document is missing.
- The fixture is missing.
- Required links are missing.
- `planning_only` is not true.
- Any runtime implementation or approval flag changes to true.
- Source-check is not required before runtime.
- Negative tests are not required before runtime.
- The metadata-only listener skeleton file is missing from the fixture.
- A forbidden source marker appears in the metadata-only listener skeleton file.
- The document or fixture introduces raw body keys, credential examples, target
  identifiers, local path detail, guarantee wording, or final severity claims.

- Socket, bind, or listen behavior.
- Transport or protocol handler.
- Executable tool registration.
- Actual tool execution.
- Local evidence reader.

output bundle structure, audit behavior, release state, or local file access.
