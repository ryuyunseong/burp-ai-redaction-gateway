# v0.10 Transport Runtime Decision

## Purpose

This decision closes the v0.10 transport/listener planning path without opening
actual transport runtime. It records that v0.10 should move to release readiness
after this decision, while any real runtime startup remains separate future
work.

## Transport Runtime Decision

Actual transport runtime is not allowed in v0.10. The v0.10 safe scope is closed
after this decision and should move to release readiness. Any future runtime work
belongs in v0.11 or a later separately approved PR.

The allowed follow-up path is:

- `v010_release_readiness`
- `v010_release_approval`
- `v010_tag_github_release`

Any follow-up that tries to open transport runtime before release readiness is
outside this decision.

## Streamable HTTP Boundary

Streamable HTTP remains deferred. Before any future Streamable HTTP runtime is
implemented, the project must define origin validation, loopback-only local
binding rules, authentication boundaries for non-local use, session policy, and
negative tests. This decision does not parse headers, accept protocol messages,
or start an HTTP runtime.

## Stdio Boundary

Stdio runtime remains deferred. This decision does not add subprocess startup,
stdio message loops, protocol dispatch, executable registration, or tool
execution. Any future stdio runtime must be reviewed separately from listener
startup and transport runtime.

## Socket Boundary

Socket startup remains deferred. This decision does not bind, listen, accept, or
serve. A future startup PR must keep socket behavior separate from protocol
handling, tool execution, local evidence reading, raw preview, replay, and
automatic handoff.

## Protocol Handler Separation

Protocol handler work remains separate. A future protocol handler PR must consume
the existing protocol parser and dispatcher fixtures without adding transport
startup, executable registration, actual tool execution, or local evidence
reading in the same PR.

## Origin Validation Requirement

Any future HTTP transport must define an origin validation policy before runtime.
Missing, unsupported, or untrusted origin metadata must fail closed using
raw-free metadata only.

## Authentication Boundary

Non-local transport requires a separate authentication and authorization
boundary. This decision does not introduce credentials, delegated access,
credential forwarding, or authorization passthrough.

## Session Policy

Stateful transport requires a session policy before runtime. Session identifiers
must not be treated as authentication. Session identifiers must be secure,
non-deterministic, and should bind to user context where applicable.

## Token Passthrough Prohibition

Token passthrough is forbidden. Caller-provided credential values must not be
forwarded to tools, adapters, local evidence readers, dashboard actions, or
external services as an authorization substitute.

## Source-check Requirements

This decision is documentation, fixture, README link, and hygiene test only.
Runtime source files must not change in this PR.

Future source checks must continue to block runtime markers for listener
startup, transport runtime, socket behavior, HTTP runtime, stdio runtime,
protocol handling, executable tool registration, actual tool execution, local
evidence reading, file body reading, raw preview, replay, active scan, dashboard
state-changing actions, upload/import actions, and automatic handoff.

## Release Closure Decision

The next v0.10 task is release readiness. No additional approval packet,
negative fixture harness, skeleton, or runtime implementation is required before
release readiness unless this decision or an existing v0.10 baseline is found to
be incorrect.
