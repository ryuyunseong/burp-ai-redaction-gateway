# v0.7 Scope Plan

This document defines the planning boundary for v0.7 after the published
`v0.6` baseline and the post-release `v0.6.1` hotfix triage criteria. It is a
planning document only. It does not implement runtime behavior, create a tag,
modify a GitHub Release, or approve a release.

## Purpose

- Fix the v0.7 goals, non-goals, and split rules before implementation starts.
- Keep hotfix candidates separate from feature work.
- Keep MCP listener, transport, protocol handling, tool execution, and local
  evidence reading as separate review boundaries.
- Keep dashboard and MCP expansion read-only and raw-free unless a later PR
  explicitly changes that boundary after security review.

## v0.6 Completed Baseline

The completed `v0.6` baseline is the local-first gateway workflow for:

- Burp export or Burp browsing traffic processed locally.
- Redaction.
- Verify.
- Review.
- Report.
- Simple Dashboard operator checks.
- Four-file AI input candidate output bundle.
- Raw-free release evidence.
- MCP planning, registry, dry-run, schema, source-check, and listener
  acceptance evidence without runtime listener implementation.

The baseline still treats findings as candidates, risk values as drafts, and
final severity and CVSS as manual decisions.

## v0.6.1 Hotfix Boundary

The `v0.6.1` hotfix boundary is defined in
[`V0.6.1_HOTFIX_TRIAGE.md`](V0.6.1_HOTFIX_TRIAGE.md). A hotfix should be limited
to a reproducible release-related defect or a narrow documentation correction.

Hotfix work should not include new MCP runtime behavior, new dashboard actions,
new output bundle structure, new evidence intake behavior, or broad UX
features. Use the branch pattern `hotfix/v0.6.x-<short-topic>` for patch
candidates.

## v0.7 Candidate Goals

Candidate goals are grouped so each later PR can be reviewed against a narrow
security boundary.

- MCP listener skeleton planning.
- MCP listener skeleton implementation only if separately approved later.

### UX Improvement Path

- Dashboard copy polish that keeps routes read-only.
- Quickstart wording polish.
- Error message wording that uses safe aliases and status metadata only.
- Output bundle usability improvements that preserve the four-file AI input
  candidate structure.

### Local Evidence Reader Decision Path

- Threat boundary decision for local evidence reader work.
- Failure mode list for path traversal, forbidden directories, raw value
  exposure, and local-only evidence handling.
- Design-only acceptance criteria before any reader implementation.

## v0.7 Non-Goals

This scope planning PR does not approve or implement:

- MCP server listener.
- MCP transport.
- MCP protocol handler.
- Executable tool registration.
- Actual tool execution.
- Local evidence reader.
- Safe file body reader.
- Raw preview or raw download.
- Replay or active scan.
- Automatic ChatGPT handoff.
- `v0.6` tag modification.
- GitHub Release `v0.6` modification.
- Output bundle four-file structure change.
- Large refactor.

## MCP Listener Path

The listener path must proceed in small slices:

1. Listener skeleton planning.
2. Listener-facing source-check scope.
3. Listener runtime decision preflight.
4. Minimal listener runtime approval packet.
5. Listener skeleton implementation, if approved separately.
6. Transport decision, if approved separately.
7. Protocol handling decision, if approved separately.
8. Tool registration decision, if approved separately.
9. Tool execution decision, if approved separately.

Listener work must not imply transport, protocol handling, tool execution, or
local evidence reading.

## UX Improvement Path

UX work can proceed before listener runtime work when it is read-only and
raw-free. Acceptable UX planning candidates include:

- Shorter quickstart flow.
- Clearer output bundle wording.
- Dashboard status wording that uses aliases instead of local paths.
- Troubleshooting guidance for setup, verify, review, report, and dashboard
  checks.

UX-only PRs should not change capture, receiver ingest, collector forwarding,
MCP runtime behavior, file retention, HMAC behavior, CSRF behavior, or output
bundle structure.

## Local Evidence Reader Decision Boundary

Local evidence reader work is security-sensitive and remains design-only until
a separate boundary PR is approved. A later design must define:

- Allowed input roots and denied directories.
- Path traversal behavior.
- Safe alias handling.
- Raw-free errors.
- Verification gate requirements.
- Audit requirements.
- Why the four-file AI input candidate boundary remains unchanged.

## PR Split Rules

Split the following into separate PRs:

- MCP listener skeleton.
- Transport or protocol handler.
- Executable tool registration.
- Actual tool execution.
- Local evidence reader.
- Raw preview or raw download.
- Dashboard state-changing action.
- Upload or import action.
- Automatic ChatGPT handoff.
- Large refactor.
- UX copy-only changes.

Each PR should state whether it changes runtime behavior, input handling,
output bundle structure, audit behavior, or release state.

## Security Review Requirements

Before any v0.7 implementation PR, identify:

- Runtime surface added or explicitly not added.
- Whether input validation changes.
- Whether raw data handling changes.
- Whether credential, session, or personal data handling changes.
- Whether local path handling changes.
- Whether a state-changing action is added.
- Whether audit behavior changes.
- Whether the four-file AI input candidate boundary changes.

If any answer changes a security boundary, split the work into a dedicated
security-focused PR.

## Test Requirements

Each v0.7 PR should include the smallest relevant test gate:

- Document hygiene tests for planning documents.
- Source-check tests for runtime-facing files.
- Unit tests for any new helper behavior.
- Browser or smoke checks for dashboard copy changes.
- Gitleaks and git safety checks for release or evidence documents.

Runtime work should include a clear negative test for blocked behavior.

## Deferred Work

The following remain deferred until they have a separate design or approval
slice:

- MCP transport.
- MCP protocol handling.
- Actual MCP tool execution.
- Local evidence reader implementation.
- Upload or import action.
- Dashboard state-changing action.
- Replay.
- Active scan.
- Automatic ChatGPT handoff.
- Output bundle structure change.

## Explicitly Out of Scope

This document does not:

- Create or move a tag.
- Create or modify a GitHub Release.
- Implement a listener.
- Implement transport.
- Implement protocol handling.
- Register executable tools.
- Execute tools.
- Read local evidence bodies.
- Display raw traffic.
- Change redaction, verification, review, report, dashboard, audit, archive,
  HMAC, CSRF, retention, collector, or receiver behavior.
- Approve external sharing.
