# v0.7 Release Approval Packet

This document is a release approval packet only. It organizes the evidence and
checks that a human reviewer needs before a later v0.7 tag or GitHub Release
action. It does not create a tag, does not create a GitHub Release, does not
move an existing tag, and does not modify the v0.6 tag or GitHub Release.

## Purpose

- Collect the v0.7 release decision inputs in one reviewable document.
- Keep release approval separate from release execution.
- Tie the RC readiness checklist and listener local smoke evidence to the
  final human approval step.
- Preserve the local-first, raw-free, four-file AI input candidate boundary.

## Current Baseline

The current baseline includes the published v0.6 release, v0.6.1 hotfix triage
criteria, v0.7 scope plan, minimal listener runtime helper, listener local smoke
evidence, and v0.7 RC readiness checklist. The minimal listener helper remains
disabled-first and loopback-only. The release approval packet does not start a
listener, bind a port, add transport, parse protocol messages, register or
execute tools, read local evidence, or change the four-file output bundle.

The v0.6 tag and GitHub Release remain unchanged.

## Approval Packet Scope

This packet may reference:

- v0.7 RC readiness checklist status.
- Listener local smoke evidence status.
- Upload Wizard browser smoke evidence status.
- Four-file AI input candidate output bundle status.
- Release body hygiene checks.
- Tag target verification checks; tag target verification remains a separate
  approval input.
- GitHub Release draft or publish checks for a later approved action.

This packet does not approve release execution by itself. A separate explicit
human approval is required before any v0.7 tag or GitHub Release action.

## Proposed Release Target Rule

The proposed release target rule is:

`approval_packet_merge_commit_or_later_explicit_main_head`

After this packet is merged, main HEAD must be checked again. A later release
target must be either the approval packet merge commit or a later explicitly
named main HEAD. The target commit must be recorded before any tag command or
GitHub Release command is run.

## Required Release Body Hygiene

The release body must preserve these rules:

- No raw request or response content.
- No actual target identifiers.
- No credential values.
- No HMAC secret value.
- No CSRF token value.
- No full local paths.
- No safety guarantee language.
- No verified vulnerability claim.
- No fixed CVSS claim.
- Candidate findings only.
- Draft risk only.
- Manual review required.
- No automatic ChatGPT handoff claim.

## Required Tag Checks

Before a later release action:

- Confirm the v0.7 tag does not already exist.
- Confirm the selected main commit matches the proposed release target rule.
- Confirm the tag command will point to the selected commit.
- Confirm the v0.6 tag remains unchanged.
- Confirm no tag is created until separate explicit human approval is given.

## Required GitHub Release Checks

Before a later GitHub Release action:

- Confirm GitHub Release v0.7 does not already exist.
- Confirm the release target matches the selected v0.7 tag.
- Confirm the release body passes the required hygiene checks.
- Confirm GitHub Release v0.6 remains unchanged.
- Confirm no GitHub Release is created until separate explicit human approval is
  given.

## Rollback Note

Because this packet is documentation, fixture, and test evidence only, rollback
means reverting the packet merge commit and rechecking main HEAD before any
release action. A rollback does not move existing release tags and does not
modify GitHub Releases unless a later human-approved release action separately
does so.

## Human Approval Boundary

This packet can support a later release approval discussion, but it is not the
approval itself. A human must explicitly approve the v0.7 tag target and GitHub
Release action after the packet is merged and main HEAD is rechecked.

## Final Release Execution Checklist

Before a later approved release action:

- Recheck main HEAD.
- Recheck that the target commit follows
  `approval_packet_merge_commit_or_later_explicit_main_head`.
- Recheck there is no existing v0.7 tag.
- Recheck there is no existing GitHub Release v0.7.
- Re-run or confirm the required final gates.
- Recheck release body hygiene.
- Recheck candidate findings only, draft risk only, and manual review required
  language.
- Record the selected target commit.
- Request separate explicit human approval for tag creation.
- Request separate explicit human approval for GitHub Release creation.

[`V0.7_FINAL_GATE_EXECUTION.md`](V0.7_FINAL_GATE_EXECUTION.md). It records gate
