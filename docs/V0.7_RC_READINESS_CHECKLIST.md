# v0.7 RC Readiness Checklist

This document fixes the release-candidate readiness checklist for v0.7. It is
an evidence checklist only. It does not approve a tag, create a GitHub Release,
start a listener, open transport, parse protocol messages, register or execute
tools, read local evidence, or change the four-file AI input candidate output
bundle.

## Purpose

- Collect the v0.7 release-candidate readiness inputs in one reviewable place.
- Connect the minimal listener runtime helper and listener local smoke evidence
  to the final gate without treating them as release approval.
- Keep the release action boundary explicit until a separate human approval
  step.
- Preserve the raw-free, local-first, four-file output bundle boundary.

## Current Baseline

The current baseline includes the v0.6 release, v0.6.1 hotfix triage criteria,
v0.7 scope planning, minimal listener runtime helper, and listener local smoke
evidence. The listener helper remains disabled-first, loopback-only, and
metadata-only. The listener local smoke evidence records helper behavior only
and does not start a service.

The current baseline still does not include actual listener startup, socket
bind, socket listen, socket accept, a long-running server loop, MCP transport,
MCP protocol handling, executable tool registration, actual tool execution,
local evidence reading, safe file body reading, raw preview, replay, active
scan, dashboard start or stop controls, upload/import actions, or automatic
ChatGPT handoff.

## Included v0.7 Scope

The RC readiness checklist may include evidence for:

- CLI generate, verify, review, and report flows.
- Upload Wizard browser smoke evidence.
- Read-only dashboard copy and troubleshooting panels.
- Minimal listener runtime helper metadata.
- Listener local smoke evidence.
- Four-file AI input candidate output bundle.
- Raw-free review and report outputs.

## Explicitly Deferred Scope

The following remain deferred and are not approved by this checklist:

- Actual listener startup.
- Socket bind, listen, accept, or long-running server loop.
- MCP transport.
- MCP protocol handler.
- JSON-RPC parser.
- Executable tool registration.
- Actual tool execution.
- Local evidence reader.
- Safe file body reader.
- Raw preview or raw download.
- Replay or active scan.
- Automatic ChatGPT handoff.
- Dashboard start or stop control.
- Upload or import action.
- Arbitrary local file read.
- External network call.
- Environment secret access.
- Any tag or GitHub Release action without explicit approval.

## Required Release Gates

Before a v0.7 release approval packet can be considered, the following gate
results must be available:

- `compileall`
- `unittest`
- `verify_out`
- `review_demo`
- `report_demo`
- `montoya_gradle_build`
- `gitleaks_dir`
- `gitleaks_git`
- `git_safety_check`
- `git_diff_check`
- `git_status_clean`
- `pr_body_hygiene`
- `release_body_hygiene_before_release`
- `tag_target_verification_before_release`

These gate names are checklist inputs. They do not create, move, or publish a
tag or release.

## Required Security Checks

- Confirm no raw traffic is included in release evidence.
- Confirm candidate finding and draft risk language remains non-final.
- Confirm final severity and CVSS remain manual decisions.
- Confirm output bundle structure remains the existing four-file AI input
  candidate set.
- Confirm no local evidence reader, safe file body reader, or raw preview is
  introduced.
- Confirm no runtime listener, transport, protocol handler, tool registration,
  tool execution, dashboard state-changing control, upload/import action, or
  automatic handoff is introduced.

## Required Smoke Evidence

Required smoke evidence includes:

- listener local smoke evidence
- Upload Wizard browser smoke evidence
- safe-file bundle four-file evidence
- raw-free review/report evidence

The smoke evidence is release-readiness input only. It is not a release
approval and is not an external sharing approval.

## Required Documentation Checks

- README links point to the v0.7 readiness documents.
- v0.7 scope plan links to this checklist.
- Listener local smoke evidence links to this checklist.
- Minimal listener runtime implementation links to this checklist.
- Deferred runtime surfaces remain clearly marked as deferred.
- The release action boundary remains separate from readiness evidence.

## Tag and Release Approval Boundary

This checklist does not create a tag, create a GitHub Release, update the v0.6
tag, update GitHub Release v0.6, create a v0.7 tag, or create GitHub Release
v0.7.

A later approval packet must separately verify the target commit, release body
hygiene, tag target verification, tag creation command, release creation
command, rollback note, and human approval before any tag or GitHub Release
action. The packet is tracked in
[`V0.7_RELEASE_APPROVAL_PACKET.md`](V0.7_RELEASE_APPROVAL_PACKET.md).

The approval packet must keep release body hygiene and tag target verification
as separate checks.

## Failure Handling

If any gate fails, keep v0.7 release approval blocked. Record only raw-free
metadata about the failure. Do not copy raw traffic, local evidence bodies,
credential values, target identifiers, local paths, stack trace bodies, or
safe file bodies into release evidence.

If a gate failure points to runtime behavior, split the fix into a separate PR
before restarting release readiness.

## Final Go/No-Go Checklist

- All required release gates are available and pass.
- Required smoke evidence is available and raw-free.
- Output bundle remains the four-file AI input candidate set.
- Candidate finding, draft risk, and manual final severity/CVSS boundaries are
  still visible.
- Deferred listener, transport, protocol, tool, local reader, dashboard,
  upload/import, raw preview, replay, active scan, and automatic handoff work
  remains out of scope.
- Tag and GitHub Release actions remain blocked until explicit approval.
