# v0.9 Protocol Parser Approval Packet

This approval packet fixes the protocol parser boundary before any parser
implementation starts. It is documentation, fixture, and negative-test planning
only. It does not implement a protocol parser, a JSON-RPC parser, a dispatcher,
a listener, transport runtime, executable tool registration, tool execution, or
local evidence reading.

## Purpose

- Define the malformed input classes that a future protocol parser must block.
- Define raw-free blocked response requirements before parser code exists.
- Define value classes that must never be echoed back from malformed input.
- Fix parser source-check and negative-test expectations before implementation.
- Keep parser work separate from dispatcher, tool execution, transport, and
  local evidence reading.

## Malformed Input Classes

Future parser negative tests must include at least:

- `empty_message`
- `invalid_json_shape`
- `unsupported_protocol_version`
- `unknown_method`
- `missing_required_field`
- `oversized_message`
- `nested_payload_too_deep`
- `raw_value_probe`
- `credential_echo_probe`
- `local_path_echo_probe`
- `target_identifier_echo_probe`

Each class must be blocked with safe metadata only. The parser must not echo
input bodies or extracted sensitive values in response fields.

## Blocked Response Requirements

Blocked parser responses may include only:

- `status`
- `reason_code`
- `parser_approved`
- `raw_data_included`
- `manual_review_required`
- `safe_message`

Blocked parser responses must not include:

- the original input text
- raw request or response content
- cookie, authorization, token, or session values
- actual target identifiers
- actual URL, domain, or IP values
- full local paths
- stack trace bodies
- local-only filenames
- tool execution results
- local evidence bodies

Every blocked response must set `parser_approved` to false,
`raw_data_included` to false, and `manual_review_required` to true.

## Echo-forbidden Value Classes

The future parser must never echo values from these classes:

- `raw_request_response`
- `credential_value`
- `token_value`
- `session_value`
- `target_identifier`
- `url_domain_ip`
- `full_local_path`
- `local_only_filename`
- `stack_trace`
- `local_evidence_body`

Tests may use synthetic labels for these classes, but must not include real
values.

## Source-check Requirements

Before parser implementation starts, a future source-check must verify:

- parser files are declared before they are added
- parser implementation markers are reviewed before merge
- dispatcher markers remain absent from parser-only PRs
- executable tool registration markers remain absent
- actual tool execution markers remain absent
- local evidence reader markers remain absent
- raw preview or download markers remain absent
- tag and GitHub Release mutation markers remain absent

## Required Negative Tests

Future parser implementation must be blocked until tests cover:

- `malformed_input_blocked`
- `raw_value_not_echoed`
- `credential_value_not_echoed`
- `target_identifier_not_echoed`
- `local_path_not_echoed`
- `unknown_method_blocked`
- `oversized_message_blocked`
- `dispatcher_absent`
- `tool_execution_absent`
- `local_evidence_reader_absent`

These tests belong to the future parser PR or a dedicated parser negative
harness PR. They are not implemented by this approval packet.

## PR Split Requirements

The following must remain separate:

- protocol parser implementation from dispatcher implementation
- protocol parser implementation from listener startup
- protocol parser implementation from transport runtime
- protocol parser implementation from executable tool registration
- dispatcher implementation from actual tool execution
- read-only tool registry contract from actual tool execution
- local evidence reader from parser, dispatcher, registry, and runtime work
- raw preview or download from local evidence reader
- automatic ChatGPT handoff from every parser and runtime PR

## Security Review Checklist

Reviewers should confirm:

- the packet is approval-only
- malformed input classes are complete enough for a first parser slice
- blocked response allowed fields are raw-free
- echo-forbidden classes include raw, credential, target, path, and evidence
  body categories
- parser work remains separate from dispatcher and execution
- local evidence reader remains deferred
- output bundle files remain unchanged
- no tag or GitHub Release is created or modified
