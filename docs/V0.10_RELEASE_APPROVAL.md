## Tag and GitHub Release execution rule

This document does not authorize tag creation or GitHub Release publication by
itself. The final release step requires a separate explicit approval that names:

- the tag name;
- the exact target commit;
- the release title;
- the release body source;
- whether publication should proceed.

Do not run `gh release create v0.10` by itself. That command can create a tag at
an unintended default-branch target if no matching tag already exists.

Use one of these release execution patterns only after explicit approval:

- create the annotated tag at the approved commit first, push that tag, and run
  `gh release create v0.10 --verify-tag`; or
- run `gh release create v0.10 --target <approved-commit-sha>` with the approved
  release body source.

After publication, verify that the `v0.10` tag points to the approved commit and
that the GitHub Release body still states that v0.10 does not include transport
or listener runtime.
