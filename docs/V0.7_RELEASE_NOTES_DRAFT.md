# v0.7 Release Notes Draft

This document is a GitHub Release body draft for later human review. It does
not create a tag, does not create a GitHub Release, does not modify the v0.6
tag or GitHub Release, and does not start or expand any runtime surface.

## Purpose

- Prepare a reviewable v0.7 release body before any release action.
- Keep release notes drafting separate from tag and GitHub Release execution.
- Preserve the local-first, raw-free, four-file AI input candidate boundary.
- Keep candidate findings, draft risk, and manual review boundaries visible.

## Release title draft

`v0.7`

## Release target rule

The target rule remains:

`approval_packet_merge_commit_or_later_explicit_main_head`

The target commit must be rechecked before release. This draft does not select
or create a tag target.

## Summary

v0.7 continues the local Burp export and browsing traffic safety gateway. It
keeps redaction, verification, review, and report generation local, and keeps
the AI input candidate bundle limited to the existing four files.

## Included changes

- Local redaction, verify, review, and report workflows.
- Upload Wizard workflow and browser smoke evidence.
- RC readiness checklist, release approval packet, and final gate evidence.
- Minimal listener runtime helper.
- Listener local smoke evidence for the helper boundary.

The minimal listener runtime helper is disabled-first, loopback-only, and metadata-only.
It is present to document and test the boundary, not to start a service.

## Security and privacy boundaries

- Candidate findings only.
- Draft risk only.
- Manual review required.
- Final severity and scoring remain manual decisions.
- Raw traffic is not included in release evidence.
- The AI input candidate bundle remains the existing four-file structure.

## Deferred scope

v0.7 does not include:

- Actual listener startup.
- Socket bind, listen, or accept behavior.
- MCP transport.
- MCP protocol handler.
- JSON-RPC parser.
- Executable tool registration.
- Actual tool execution.
- Local evidence reader.
- Safe file body reader.
- Raw preview or raw download.
- Replay or active scan.
- Dashboard start or stop control.
- Upload or import action.
- Automatic ChatGPT handoff.

## Validation evidence

The release notes draft consumes the existing v0.7 evidence chain:

- RC readiness checklist.
- Release approval packet.
- Final gate execution evidence.
- Listener local smoke evidence.
- Minimal listener runtime helper evidence.

Before any later release action, the selected target commit, v0.7 tag absence,
GitHub Release v0.7 absence, release body hygiene, and final gate freshness
must be rechecked.

## Manual review boundaries

The release body must not claim that findings are verified issues. It must not
claim that risk scoring is final. It must not claim external sharing approval.
The release body is review input until separate explicit human approval names
the target commit, tag name, title, and body.

## Not a release execution

This draft does not create a tag, create a GitHub Release, move any tag,
publish any release, start a listener, open transport, parse protocol messages,
register tools, execute tools, read local evidence, preview raw data, or send
anything to ChatGPT automatically.

## Final approval requirements

A later release action requires separate explicit human approval for:

- The target commit.
- The v0.7 tag creation.
- The GitHub Release title and body.
- The GitHub Release creation or publish action.

If main changes before that approval, recheck the final gate evidence and the
release body hygiene rules before proceeding.
