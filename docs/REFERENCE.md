# 구성과 추가 설정

처음 사용할 때는 [README](../README.md)를 따라 하면 됩니다.
기본 파일 처리에는 대시보드만 있으면 됩니다. 아래 연결과 감사 기능은 필요할 때만 설정하세요.

## 필요한 설정

| 하려는 일 | 필요한 설정 | 안내 |
| --- | --- | --- |
| 파일 처리와 결과 확인 | 추가 설정 없음 | [사용 방법](USAGE.md) |
| 명령어로 파일 처리 | README.md가 있는 폴더에서 실행 | [명령어와 오류 해결](USAGE.md) |
| Burp 기록 가져오기 (선택) | 내 컴퓨터의 수신기에 연결 | [Burp 수집기](MONTOYA_COLLECTOR.md) |
| Codex에서 결과 읽기 (선택) | 읽을 결과 폴더만 MCP에 연결 | [읽기 전용 MCP](READ_ONLY_MCP.md) |
| 처리 이력 점검 (선택) | 감사 기록이 필요한 경우에만 사용 | [감사 기록 안내](AUDIT_OPERATIONS_GUIDE.md) |

대시보드의 기본 포트는 8766, Burp 수신기는 8765입니다. 포트가 겹치면 각 안내에 따라 바꾸세요.
외부 주소에 공개하지 말고 내 컴퓨터에서만 연결하는 설정을 유지합니다.
MCP로 조회한 내용은 AI 도구에 전달되므로, 연결할 자료를 공유해도 되는지 먼저 확인하세요.

## 정책을 확인할 때

- 민감정보 처리와 검사 기준은 [policy.json](../policy.json)에 있습니다. 기본 사용에는 변경이 필요하지 않습니다.
- 검사를 통과시키려고 규칙을 끄지 마세요. 오탐 예외가 꼭 필요하면 `verification.allowlist_notes`에 이유와 좁은 허용 범위를 남깁니다.
- 기본 허용 목록은 네트워크 분류값을 위한 것입니다. 실제 대상 주소·내부 호스트 IP·쿠키·토큰 값을 허용하지 마세요.
- 감사 기록의 HMAC은 변조 확인용이지 암호화가 아닙니다. 압축 파일 검사만으로 원래 로그와 HMAC 검사를 대신하지 않습니다.

## 보안 주의사항

- 검증에 실패한 결과는 보고서나 AI 검토에 사용하지 않습니다. 자동 검사 후에도 파일을 직접 확인하세요.
- 검토 후보는 확정 취약점이 아닙니다. 최종 심각도·CVSS는 직접 재현하고 영향을 확인한 뒤 판단합니다.
- 원본 요청·응답, 인증정보, 개인정보, 실제 대상 주소, 전체 로컬 경로와 비밀 설정값은 공유하지 않습니다.
- 실제 Burp 기록은 `local_only/`에만 보관하고, `samples/`에는 가상 자료만 둡니다.
- `local_only/`, `out/`, `exports/`, `reports/`, `raw/`, `raw_vault/`, 감사 로그와 보관 목록 파일은 커밋하지 않습니다.
- 원문 조회, 요청 재전송, 능동 스캔, 자동 AI 전송은 제공하지 않습니다. MCP도 Burp를 직접 조작하지 않습니다.

## 개발과 검증

코드는 `burp_ai_redaction_gateway/`, 테스트는 `tests/`, 가상 샘플은 `samples/`에 있습니다.
README.md가 있는 폴더의 PowerShell에서 실행합니다.

```powershell
python -m compileall burp_ai_redaction_gateway tests
python -m unittest discover -s tests
scripts\git_safety_check.bat
```

마지막 명령은 결과 검증과 민감정보 검사도 수행합니다. 테스트 통과가 실제 서비스의 취약점 재현이나 외부 공유 허가를 뜻하지는 않습니다.
