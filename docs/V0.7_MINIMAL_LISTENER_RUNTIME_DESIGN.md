# v0.7 Minimal Listener Runtime Design

This document fixes the design boundary for a future minimal listener runtime
implementation PR. It is documentation, fixture, and test scope only. It does
not implement listener runtime behavior, socket behavior, transport, protocol
handling, executable tool registration, actual tool execution, local evidence
reading, safe file body reading, raw preview, replay, active scan, dashboard
state-changing control, upload or import action, or automatic ChatGPT handoff.

## Purpose

- Define the smallest reviewable listener runtime boundary before any runtime
  implementation exists.
- Keep listener runtime separate from transport, protocol handling, executable
  tool registration, actual tool execution, local evidence reading, and
  dashboard state-changing controls.
- Require local-only, loopback-only, disabled-by-default, raw-free error
  behavior for any later runtime implementation.
- Keep the `v0.6` tag, GitHub Release `v0.6`, and four-file AI input candidate
  output bundle unchanged.

## Design Scope

This design records the constraints a later minimal listener runtime
implementation PR must satisfy before review. It does not approve that later
implementation.

The design scope is limited to:

- Future listener boundary requirements.
- Local-only and loopback-only constraints.
- Disabled-by-default requirements.
- Raw-free blocked and error response expectations.
- Source-check requirements.
- Required negative tests.
- Security review checklist.
- PR split requirements.
- Rollback and disablement expectations.

## Allowed Future Listener Runtime Boundary

A later minimal listener runtime implementation PR may be considered only if it
is:

- Local-only.
- Loopback-only.
- Disabled by default.
- Limited to listener boundary behavior.
- Free of transport implementation.
- Free of protocol handling.
- Free of executable tool registration.
- Free of actual tool execution.
- Free of local evidence body reads.
- Free of safe file body reads.
- Free of raw preview and raw download behavior.
- Free of replay and active scan behavior.
- Free of automatic ChatGPT handoff.
- Covered by explicit negative tests.
- Covered by source-check declared file scope.
- Designed with raw-free blocked and error responses.

The later PR must not silently include transport, protocol handling, executable
tool registration, actual tool execution, local evidence reading, dashboard
state-changing controls, upload or import actions, or output bundle structure
changes.

## Local-only and Loopback-only Constraints

A later runtime implementation must document:

- How it prevents non-loopback bind behavior.
- How it rejects remote access by default.
- How it keeps runtime exposure on the local machine only.
- How it avoids external network calls.
- How it avoids automatic handoff to any external service.

This design does not add the runtime mechanism. It only records the required
constraints for a later PR.

## Disabled-by-default Requirement

A later runtime implementation must remain disabled by default. The later PR
must document:

- The default disabled state.
- The local operator action required to enable it.
- The raw-free blocked response when disabled.
- The disablement path after it has been enabled.
- The rollback path if the listener must be removed.

## Raw-free Error Behavior

Any later listener runtime implementation must return only raw-free metadata for
blocked or failed requests. It must not echo:

- Original body values.
- Credential values.
- Target identifiers.
- Local path details.
- Safe file body contents.
- Stack trace body content.

Blocked responses should use stable status and reason codes that do not contain
caller-provided body text.

## Source-check Requirements

Before any listener runtime file is added, the PR must update source-check
scope so new listener-facing files are declared and scanned.

The source-check must continue to block accidental introduction of:

- Transport implementation.
- Protocol handler implementation.
- Executable tool registration.
- Actual tool execution.
- Local evidence reader.
- Safe file body reader.
- Raw preview or raw download.
- Replay or active scan.
- Automatic ChatGPT handoff.
- Dashboard state-changing control.
- Upload or import action.

## Required Negative Tests

A later runtime implementation PR must include negative tests for:

- `remote_bind_blocked`
- `disabled_by_default`
- `protocol_message_rejected`
- `transport_absent`
- `tool_registration_absent`
- `tool_execution_absent`
- `local_evidence_read_absent`
- `raw_preview_absent`
- `automatic_handoff_absent`
- `dashboard_control_absent`

These tests belong in the later implementation PR. This design PR only fixes
the expected negative-test list.

## Security Review Checklist

Before a later minimal listener runtime PR is approved, reviewers should
confirm:

- The listener is local-only.
- The listener is loopback-only.
- The listener is disabled by default.
- Remote bind behavior is blocked.
- No transport implementation is included.
- No protocol handler is included.
- No executable tool registration is included.
- No actual tool execution is included.
- No local evidence reader is included.
- No safe file body reader is included.
- No raw preview or raw download is included.
- No replay or active scan is included.
- No automatic ChatGPT handoff is included.
- No dashboard state-changing control is included.
- No upload or import action is included.
- Error responses are raw-free.
- The four-file AI input candidate output bundle is unchanged.
- `v0.6` tag and GitHub Release `v0.6` are unchanged.

## PR Split Requirements

The following must remain separate PRs:

- Minimal listener runtime implementation.
- Socket bind, listen, or accept behavior.
- Transport or protocol handler.
- Executable tool registration.
- Actual tool execution.
- Local evidence reader.
- Safe file body reader.
- Raw preview or raw download.
- Dashboard state-changing action.
- Upload or import action.
- Automatic ChatGPT handoff.

Each later PR must state whether it changes runtime behavior, input handling,
local file access, audit behavior, output bundle structure, or release state.

## Rollback and Disablement Expectations

A later minimal listener runtime implementation must have:

- A disabled-by-default mode.
- A documented disablement path.
- Raw-free blocked responses.
- A rollback plan that removes the listener runtime without touching the
  four-file AI input candidate output bundle.
- No release action unless separately approved.

This design does not create the disablement mechanism. It only records that the
later runtime implementation must provide one.
