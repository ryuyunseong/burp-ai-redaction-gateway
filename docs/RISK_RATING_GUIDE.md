# Risk Rating Guide

This guide explains how Burp AI Redaction Gateway treats evidence confidence,
risk rating drafts, risk profiles, severity decisions, and CVSS.

The short version:

```text
evidence confidence != severity
risk_rating_draft != severity decision
strict profile != confirmed High
CVSS != generated automatically
```

Use this guide after generated output has passed `verify`.

## Safety Boundary

Risk rating uses sanitized finding candidate metadata only. It must not use or
print raw request or response data, Cookie values, Authorization values, tokens,
JWTs, session values, real domains, internal IPs, customer names, or personal
data.

The following files may contain risk rating draft metadata after verification:

- `finding_candidates.json`
- `analysis_packet.json`
- `chatgpt_prompt.md`
- `codex_task_prompt.md`
- `report_draft.md`

These files remain review material. They are not a final customer report.

## Concept Definitions

| Concept | Meaning | Generated by this project |
| --- | --- | --- |
| Evidence confidence | How strongly the sanitized evidence supports the candidate finding. | Yes |
| Likelihood draft | A draft estimate of how likely the issue may be exploitable or relevant. | Yes |
| Impact draft | A draft estimate of possible business or security impact. | Yes |
| Severity draft | A draft combination of likelihood and impact. | Yes |
| Severity decision | A human decision after reproduction, scope checks, and impact review. | No |
| CVSS | A separate vulnerability scoring framework. | No |

`confidence` is about evidence quality. It is not severity.

`risk_rating_draft` is a draft risk review aid. It is not a severity decision
and it is not a CVSS score.

## Risk Profiles

The project supports three risk rating draft profiles.

| Profile | Intended use | Behavior |
| --- | --- | --- |
| `conservative` | Default safe profile. | Keeps draft wording cautious and avoids overstatement. |
| `consultant` | Consultant-style report drafting. | Allows a slightly more report-ready draft posture while preserving manual verification requirements. |
| `strict` | Sensitive candidate surfacing. | Treats some candidate patterns more cautiously by raising draft likelihood or severity, but still does not confirm severity. |

`strict` means "review this more carefully." It does not mean "confirmed High."

The default profile is `conservative`.

## How Draft Values Are Used

The generator records draft metadata like this:

```json
{
  "risk_profile": "conservative",
  "likelihood_draft": "medium",
  "impact_draft": "medium",
  "severity_draft": "medium",
  "confidence_is_severity": false,
  "risk_rating_finalized": false,
  "manual_verification_required": true
}
```

The exact draft values depend on the finding type, evidence confidence, and
selected profile. They are meant to help reviewers prioritize manual checks.

Do not convert `confidence` into severity. Do not copy `severity_draft` into a
final report without manual review.

## Manual Severity Review

Before making a severity decision, review at least:

1. Whether the candidate can be reproduced in an authorized Burp workflow.
2. Whether the affected behavior exists in the intended deployment path.
3. Whether different roles, users, tenants, or authorization states change the
   result.
4. Whether the affected data or action has real business or security impact.
5. Whether compensating controls or environment constraints reduce likelihood
   or impact.
6. Whether the finding should be mapped to a separate CVSS score.

Keep the report wording as candidate or suspected until the manual review is
complete.

## CVSS Boundary

CVSS is a separate scoring workflow. This project does not assign CVSS scores.

If CVSS is needed, calculate it after manual reproduction and impact review.
Keep the CVSS worksheet or reasoning separate from the generated
`risk_rating_draft` metadata.

## Profile Selection Guidance

Use `conservative` when:

- The output may be shared early.
- Evidence is incomplete.
- You want the safest default language.

Use `consultant` when:

- You are preparing a report draft for expert review.
- You still need manual reproduction before making claims.
- You want report-friendly structure without confirmed severity language.

Use `strict` when:

- Missing a potential candidate would be worse than reviewing extra candidates.
- The environment requires more sensitive triage.
- You still understand that the profile is draft-only.

## Safe Wording

Prefer:

- "Risk rating draft"
- "Severity draft"
- "Manual severity review required"
- "Evidence confidence is not severity"
- "CVSS is separate scope"

Avoid:

- "Confirmed vulnerability"
- "Confirmed severity"
- "Confirmed CVSS"
- "High severity because confidence is high"
- "Exploitation proven" without separate proof

## Troubleshooting

If a profile looks too aggressive, rerun generation with `--risk-profile
conservative` and compare the draft values.

If report wording looks too certain, keep the finding as a candidate and adjust
the report text after manual verification.

If a customer or organization has its own rating model, treat this project's
draft as input to that model, not a replacement for it.
