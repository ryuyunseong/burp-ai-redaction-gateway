# v0.7 Minimal Listener Runtime Implementation Decision

This document fixes the final implementation decision boundary before a
separate minimal listener runtime implementation PR can be proposed. It is
documentation, fixture, and test scope only. It does not implement listener
runtime behavior, socket behavior, transport, protocol handling, executable
tool registration, actual tool execution, local evidence reading, safe file
body reading, raw preview, replay, active scan, dashboard state-changing
control, upload or import action, or automatic ChatGPT handoff.

## Purpose

- Decide whether a separate minimal listener runtime implementation PR may be
  proposed next.
- Keep that future implementation limited to a local-only, loopback-only,
  disabled-by-default listener boundary.
- Require the future implementation PR to consume the source-check consumption
  guard and listener negative harness fixture as actual tests.
- Keep the `v0.6` tag, GitHub Release `v0.6`, and four-file AI input candidate
  output bundle unchanged.

## Implementation Decision

This decision does not implement listener runtime behavior.

The implementation decision is:

- `minimal_listener_runtime_may_be_proposed_next: true`
- This PR itself is not runtime implementation.
- The next implementation PR must be local-only.
- The next implementation PR must be loopback-only.
- The next implementation PR must be disabled by default.
- The next implementation PR must not include transport.
- The next implementation PR must not include protocol handling.
- The next implementation PR must not include executable tool registration.
- The next implementation PR must not include actual tool execution.
- The next implementation PR must not include local evidence reading.
- The next implementation PR must connect the source-check consumption fixture
  and negative harness fixture to actual tests.

This decision only permits a proposal for a separate minimal implementation PR.
It does not approve merging that future implementation without its own review,
negative tests, source-check coverage, and local smoke evidence.

The follow-up minimal listener runtime implementation is tracked in
[`V0.7_MINIMAL_LISTENER_RUNTIME_IMPLEMENTATION.md`](V0.7_MINIMAL_LISTENER_RUNTIME_IMPLEMENTATION.md).
That follow-up scope is limited to disabled-by-default, loopback-only startup
validation and raw-free blocked/disabled response helpers. It still excludes
transport, protocol handling, tool execution, local evidence reading, dashboard
state-changing control, upload/import behavior, and automatic ChatGPT handoff.

## Required Rollback and Disablement

The future implementation PR must include:

- Disabled-by-default behavior.
- A documented disablement path.
- Raw-free blocked and disabled responses.
- A rollback plan that removes the listener runtime without changing the
  four-file AI input candidate output bundle.
- No release action unless separately approved.

This decision does not create the disablement mechanism. It only records that
the future implementation PR must provide one.
